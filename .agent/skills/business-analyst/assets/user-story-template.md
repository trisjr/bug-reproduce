# User Story Template & Guidelines

## 1. The Standard Format
**Title**: [Short specific title]

> **As a** [Role/Persona],
> **I want to** [Action/Feature],
> **So that** [Value/Benefit].

## 2. INVEST Criteria (Checklist)
Ensure your story meets these criteria:
- [ ] **I**ndependent: Can be developed separately?
- [ ] **N**egotiable: Is it open to discussion?
- [ ] **V**aluable: Does it deliver value to the user?
- [ ] **E**stimable: Can dev team estimate the effort?
- [ ] **S**mall: Can it be completed in one sprint?
- [ ] **T**estable: Are there clear acceptance criteria?

## 3. Acceptance Criteria (Gherkin Syntax)

### Scenario 1: Happy Path
**Given** [Pre-condition / Initial State]
**And** [Additional context]
**When** [User performs specific action]
**Then** [System responds with expected result]
**And** [State changes]

### Scenario 2: Edge Case / Error Handling
**Given** [Pre-condition]
**When** [User performs invalid action]
**Then** [System shows specific error message]
**And** [System state remains unchanged]

## 4. Definition of Ready (DoR) checklist
- [ ] Story defined clearly
- [ ] Acceptance criteria defined
- [ ] Dependencies identified
- [ ] UX/UI attached (if applicable)
- [ ] Performance criteria defined (if applicable)
